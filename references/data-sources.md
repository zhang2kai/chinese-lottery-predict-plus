# 数据来源与校验

## 来源优先级

按数据发布者的可信度选择来源，不依赖固定工具名称：

1. 彩票发行机构的官方开奖页面或官方公开数据；
2. 官方授权渠道或可追溯的权威媒体；
3. 提供明确出处和完整期号的独立历史数据服务。

优先使用官方来源。不要硬编码可能变更的页面 URL；每次通过当前可用的网页搜索能力定位最新官方页面，并记录最终页面 URL。

## 交叉核对

- 最新一期的期号、开奖日期和号码必须与官方来源一致。
- 如果能够取得两个完整数据集，应比较整个统计窗口。
- 只有一个官方来源可用时，可以继续，但必须在输出中标明「单一官方来源，未完成独立交叉核对」。
- 官方来源不可用时，至少需要两个相互独立的可信来源，且统计窗口内的数据必须一致。
- 同等级权威来源存在无法解释的冲突时，停止分析并列出冲突字段。
- 普通第三方来源与已确认的官方记录冲突时，以官方记录为准，同时披露第三方冲突。

## 数据窗口

- 用户未指定时，默认使用最近 `100` 个校验通过的已开奖期次。
- 数据必须按开奖日期排序，并标注最早期号、最新期号和有效期数。
- 输入数据少于请求窗口时，停止分析，不得缩小窗口后静默继续。
- 不根据期号数值推断连续性。若来源明确显示缺期，应停止并说明缺失期号。
- 不得把尚未开奖、日期位于未来或号码不完整的期次计入窗口。

## 标准输入格式

`scripts/analyze_draws.py` 接收一个 UTF-8 JSON 文件：

```json
{
  "lottery": "SSQ",
  "sources": [
    {
      "name": "来源名称",
      "url": "https://example.com/draws",
      "retrieved_at": "2026-09-11T10:30:00+08:00"
    }
  ],
  "verification": {
    "status": "single-official-source",
    "note": "使用单一官方来源，未完成独立交叉核对"
  },
  "draws": [
    {
      "issue": "2026001",
      "date": "2026-01-01",
      "primary": [1, 2, 3, 4, 5, 6],
      "secondary": [7]
    }
  ]
}
```

字段映射：

- SSQ：`primary` 表示红球，`secondary` 表示蓝球。
- DLT：`primary` 表示前区，`secondary` 表示后区。

## 必须校验

- `lottery` 只能是 `SSQ` 或 `DLT`。
- `sources` 至少包含一个来源；每个来源包含名称、HTTP(S) URL 和带时区的检索时间。
- `verification.status` 只能是 `cross-checked`、`single-official-source` 或 `official-source-with-disclosed-conflict`。
- `verification.note` 必须简要说明核对方式或未完成交叉核对的原因。
- 每期开奖数据包含期号、ISO 日期、主号码区和附加号码区。
- 期号不得重复。
- 开奖日期不得晚于运行脚本当天的日期。
- 号码数量、范围和唯一性符合 [彩票规则](lottery-rules.md)。
- 统计窗口的有效记录数量不少于请求数量。

来源名称、URL 和检索时间是数据集级元数据，不需要在每期开奖记录中重复。
